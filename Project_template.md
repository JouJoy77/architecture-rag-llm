# Проект: RAG-бот для QuantumForge Software

## Задание 1. Исследование моделей и инфраструктуры

### Задача и ограничения

Заказчик — техническое руководство QuantumForge Software. Пользователи — разработчики, поддержка, менеджеры, аналитики и новые сотрудники. GRC-команде нужны актуальные политики и ссылки на документы для подготовки к аудитам.

Бот должен отвечать со ссылками на документацию и говорить «не знаю», если данных недостаточно. Повторяющиеся вопросы без ответа покажут пробелы в базе. Пользу проверим на пилоте по времени поиска до и после внедрения.

Объём — около 21 тысячи файлов и страниц плюс 250 PDF, прирост — 400 страниц в месяц. Нагрузка, языки и размеры текстов не заданы. Для расчёта приму 10 тысяч запросов в месяц, русский и английский языки, 50 млн токенов после разбиения. Это допущения.

До загрузки нужно определить владельцев, актуальные версии и права доступа, убрать дубли. Для PDF потребуется извлечение текста, для сканов и поломанных PDF — OCR.

Если документы нельзя передавать провайдеру, локальными должны быть и эмбеддинги, и LLM. Локальный индекс с облачной LLM всё равно передаёт контекст наружу. Права сотрудника проверяются до передачи фрагментов модели.

### 1. Сравнение LLM

Hugging Face — площадка с моделями, поэтому для сравнения беру конкретную локальную модель: Qwen3.5-9B в квантовании Q5_K_M. Облачные варианты — OpenAI GPT-5.4 mini и YandexGPT Pro 5.1.

| Критерий | Qwen3.5-9B локально | OpenAI GPT-5.4 mini | YandexGPT Pro 5.1 |
| --- | --- | --- | --- |
| Качество | По данным разработчика: MMLU-Pro 82,5, IFEval 91,5, LongBench v2 55,2. Это результаты исходной модели, не нашей сборки Q5_K_M без thinking | Разработчик позиционирует модель для задач программирования, работы с инструментами и агентных сценариев. В изученной API-карточке нет результатов перечисленных слева тестов | По оценке Яндекса, выигрывает у GPT-4.1 в 56% сравнений на его наборе задач. Основной акцент на русском языке |
| Скорость | Планируется полная загрузка слоёв на GPU 12 ГБ, без вычисления слоёв на CPU. Фактическая задержка зависит от контекста и настроек | Зависит от сети, лимитов API и нагрузки провайдера | Те же ограничения API; для диалога — синхронный режим или streaming |
| Стоимость | Нет платы за токены. Есть сервер, электричество или аренда GPU, обновления и сопровождение | Оплата входных и выходных токенов. При небольшой нагрузке обычно дешевле постоянно работающего GPU | Оплата токенов; цена зависит от модели и режима вызова |
| Развёртывание | Нужно загрузить веса, настроить inference-сервер, драйверы и мониторинг | API, ключ, лимиты, обработка ошибок и повторов | API, облачный аккаунт, сервисные права и обработка ошибок |
| Данные | Обработка в инфраструктуре компании после загрузки моделей | Вопрос и контекст передаются провайдеру | Вопрос и контекст передаются провайдеру |

Выбираю Qwen3.5-9B Q5_K_M для своего компьютера. Это более новое поколение Qwen; в карточке опубликованы тесты на следование инструкциям, работу с контекстом и разные языки. Для справочного RAG начну с режима без thinking. [Карточка модели](https://huggingface.co/Qwen/Qwen3.5-9B).

У меня 12 ГБ VRAM. Файл весов выбранной сборки занимает около 7,1 ГБ, поэтому остаётся запас под KV-кэш и вычислительные буферы. Полную загрузку слоёв на GPU проверю с контекстом 4096 токенов. Эмбеддинги и FAISS, вероятно, будут работать на CPU.

Качество моделей сравниваю по опубликованным бенчмаркам и оценкам разработчиков. Облачные API в учебном проекте не подключаю; их стоимость ниже рассчитана только для сравнения вариантов.

Показатели Qwen также не являются замером нашей квантованной сборки без thinking. Выбираю Qwen по опубликованным результатам, возможности локального запуска и доступной памяти, без утверждения о равенстве с GPT или YandexGPT. Ответы по источникам, ссылки и отказы проверю локально на своей базе.

OpenAI API по умолчанию не использует данные для обучения, но журналы контроля злоупотреблений могут храниться до 30 дней. Перед подключением любого облака нужно проверить условия хранения и регион обработки. [OpenAI Data controls](https://developers.openai.com/api/docs/guides/your-data).

### 2. Сравнение эмбеддингов

Sentence-Transformers — библиотека для запуска моделей. Локальный кандидат — `intfloat/multilingual-e5-base`, облачный — `text-embedding-3-small`.

| Критерий | multilingual-e5-base через Sentence-Transformers | OpenAI text-embedding-3-small |
| --- | --- | --- |
| Размер вектора | 768 | 1536 по умолчанию; можно уменьшить параметром API |
| Скорость индексации | На CPU зависит от числа ядер и размера batch; GPU позволяет обрабатывать тексты пакетами быстрее. Нет сетевых запросов | Пакетные запросы к API; скорость ограничивают сеть, квоты и rate limits |
| Качество поиска | Многоязычная модель для поиска, подходит для проверки запросов на русском по английским документам | Многоязычный кандидат; качество на внутренних терминах нужно сравнить с локальной моделью |
| Стоимость | Вычисления и сопровождение, без платы за каждый текст | $0.02 за 1 млн входных токенов по стандартному тарифу |
| Конфиденциальность | Тексты и запросы остаются внутри компании | Для индексации тексты, а при поиске запросы передаются в API |

Выбираю **multilingual-e5-base**: префиксы `query: ` и `passage: `, нормализованные векторы, одна версия модели при индексации и поиске. Лимит входа — 512 токенов; чанки планирую до 450 токенов её токенизатора с запасом под заголовок и префикс. [Карточка модели](https://huggingface.co/intfloat/multilingual-e5-base).

Размерности OpenAI приведены в [руководстве по эмбеддингам](https://developers.openai.com/api/docs/guides/embeddings), цена — в [карточке text-embedding-3-small](https://developers.openai.com/api/docs/models/text-embedding-3-small).

Для локальной модели измерю время индексации, чанки в секунду и Recall@5 — долю релевантных фрагментов в первых пяти результатах. Вопросы должны включать перефразирования, разные языки и вымышленные термины. OpenAI Embeddings рассматривается только по опубликованным характеристикам, без платных вызовов. Смена модели требует пересчёта индекса.

### 3. ChromaDB и FAISS

Сравниваю локальную Chroma и CPU-версию FAISS. FAISS — библиотека поиска по векторам, а Chroma — хранилище с коллекциями, документами и метаданными.

| Критерий | FAISS | ChromaDB |
| --- | --- | --- |
| Поиск | `IndexFlatIP` выполняет точный перебор. По мере роста можно рассмотреть HNSW или IVF | В односерверном варианте используется приближённый поиск HNSW, с настройками баланса скорости и полноты |
| Индексация | Flat не требует обучения или построения графа: достаточно добавить готовые векторы | Построение HNSW требует дополнительных вычислений; также сохраняются документы и метаданные |
| Работа с данными | Тексты, версии и соответствие ID нужно хранить отдельно. Изменения и удаление организует приложение | Есть коллекции, добавление, обновление, удаление и фильтры по метаданным |
| Развёртывание | Работает внутри Python-процесса; отдельный сервис не нужен | Можно встроить в приложение или запустить отдельным сервером |
| Поддержка и стоимость | Нет отдельного сервера БД, но нужны код управления индексом и согласованные резервные копии | Меньше собственного кода для управления данными; в серверном режиме нужно сопровождать ещё один сервис |

Скорость зависит от типа индекса и настроек: FAISS не обязательно быстрее Chroma. Для `IndexFlatIP` нормализую векторы, чтобы скалярное произведение соответствовало cosine similarity. [Индексы FAISS](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes).

Документация Chroma: [режимы развёртывания](https://docs.trychroma.com/reference/architecture/overview), [HNSW](https://docs.trychroma.com/docs/collections/configure), [фильтры](https://docs.trychroma.com/docs/querying-collections/metadata-filtering). Проверку прав пользователя выполняет приложение, фильтры лишь ограничивают поиск.

**Для первой версии выбираю FAISS, индекс `IndexFlatIP`.** Учебная база небольшая. Корпоративный пилот тоже предварительно помещается в RAM: условные 150 тысяч векторов по 768 float32 занимают около 461 МБ (`150000 × 768 × 4`). Тексты, метаданные и модели требуют дополнительной памяти.

Индекс и метаданные сохраняются одной версией. При обновлении пересчитываются эмбеддинги изменённых документов и собирается новый снимок. Для групп доступа можно разделить индексы. Если права сильно пересекаются, обновления частые или нужен общий индекс для нескольких экземпляров бота, удобнее Chroma. Прирост в 400 страниц в месяц сам по себе пока не требует отдельной БД.

### 4. Варианты и стоимость

Тарифы проверены 1 ноября 2026 года, без скидок, кэширования и налогов. Приму 3000 входных токенов с контекстом и 400 выходных на запрос: 30 млн входных и 4 млн выходных в месяц. Фактические объёмы зависят от токенизатора провайдера.

- GPT-5.4 mini: $0.75 за 1 млн входных и $4.50 за 1 млн выходных токенов. Итого **$40.50 в месяц**, без дополнительных reasoning-токенов. [Тариф](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
- YandexGPT Pro 5.1, синхронный API: примерно $6.56 за 1 млн входных и столько же за выходные токены. Получается **около $223 в месяц**. [Тарифы Yandex AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/pricing).
- OpenAI Embeddings: первые 50 млн токенов — **$1**. Ещё 1 млн токенов изменённых чанков — **$0.02**. Запросы и повторная индексация оплачиваются отдельно. [Тариф](https://developers.openai.com/api/docs/models/text-embedding-3-small).

Условный бюджет сервера: $0.15/час без GPU или $1/час с GPU 24 ГБ. За 720 часов — $108 и $720. Это допущения для сравнения, перед закупкой нужна реальная смета.

Полная стоимость владения дополнительно включает резервные копии, мониторинг, хранение и работу инженеров. Для своего оборудования вместо аренды учитываются амортизация и электричество.

### Рекомендация

Для QuantumForge выбираю **вариант 4: Qwen3.5-9B Q5_K_M, multilingual-e5-base и FAISS локально**. Разрешение на передачу клиентских спецификаций и внутренних документов в облако не задано. Вариант 2 остаётся альтернативой для компании, если передача данных разрешена и важнее снизить расходы на небольшой нагрузке. В учебной реализации использую только локальные модели.

Стартовый сервер для корпоративного пилота — **16 vCPU, 64 ГБ RAM, GPU 24 ГБ VRAM, NVMe 500 ГБ**. Это конфигурация с запасом под больший контекст, параллельные запросы и индексацию. GPU нужна для генерации, FAISS работает на CPU. Файл весов Qwen3.5-9B Q5_K_M занимает около 7,1 ГБ; дополнительно нужны кэш контекста и рабочая память. Начну с контекста 8 тысяч токенов и двух одновременных генераций, затем проверю нагрузкой.

Для учебной базы из 30+ документов использую: актуальный llama.cpp с CUDA и поддержкой Qwen3.5, Qwen3.5-9B Q5_K_M, контекст 4096 токенов, одна генерация одновременно, thinking выключен. В контекст входят инструкции, few-shot, найденные фрагменты, вопрос и ответ. Vision-проектор для текстового RAG не загружается. Эмбеддинги и FAISS оставлю на CPU. Скорость и потребление памяти проверю при запуске; отдельная аренда GPU для разработки не нужна. Остаются электричество и амортизация компьютера. [llama.cpp](https://github.com/ggml-org/llama.cpp).

До расширения пилота проверю поиск, ссылки, отказы, права и защиту от инструкций внутри документов. Измерю p95 времени ответа при одном и двух параллельных запросах. По результатам уточню модель и ресурсы сервера.

## Задание 2. Подготовка базы знаний

Взял англоязычную Rick and Morty Wiki. Выбрал 36 страниц: 19 персонажей, 3 вида существ,
7 технологий, 5 мест, одну организацию и одно событие. Например, Portal Gun, Microverse Battery,
Central Finite Curve, The Citadel и The Battle of Blood Ridge. Английский оставил для удобства
обработки исходников; выбранные эмбеддинги поддерживают вопросы на русском.

Скрипт `prepare_knowledge_base.py` получает статьи через публичный MediaWiki API,
раскрывает перенаправления и извлекает содержательные абзацы. Удаляются HTML, инфобоксы,
навигация, таблицы с цитатами, галереи, сноски и служебные сведения о сериале и играх.
Для длинных статей выбран объём примерно до 700 слов с сохранением целых предложений.
Один файл соответствует одной сущности; разбиение на чанки будет в следующем задании.

В `terms_map.json` — 451 соответствие, включая короткие имена, варианты написания,
прозвища, названия технологий и второстепенные сущности. Основные замены заданы вручную,
дополнительные названия из ссылок и выделенных курсивом названий создаются по стабильному SHA-256.
Короткое и полное имя одной сущности связаны через цель ссылки. Ссылки на страницы
неоднозначности и описательные фразы вроде «all other Ricks» не считаются именами сущностей.
Замена выполняется одним проходом, с границами слов и приоритетом длинных совпадений.
Обычно регистр не учитывается; для неоднозначных имён вроде Unity и Summer он важен,
чтобы сохранить обычные слова unity и summer. Притяжательные окончания сохраняются,
а альтернативные версии членов семьи различаются обозначением реальности.

| Было | Стало |
| --- | --- |
| Rick Sanchez | Veyran Kest |
| Morty Smith | Talen Voss |
| Portal Gun | Rift Spindle |
| Portal Fluid | Veyl Catalyst |
| Galactic Federation | Vhalan Compact |
| Central Finite Curve | Bounded Horizon |

Результат — `knowledge_base/`: 36 Markdown-файлов, около 19,4 тысячи слов.
Скрипт проверяет количество и уникальность документов, отсутствие исходных терминов
из словаря, HTML и служебного текста. Отдельный список характерных маркеров ловит
пропуски, даже если варианта написания нет в словаре. Уникальность проверяется по тексту
без заголовков. Сводка записана в `data/kb_build_report.json`.
Пройдены 20 тестов замены имён, псевдонимов, грамматических форм, Unicode и очистки HTML.
При повторной проверке все 36 ID ревизий и SHA-256 совпали с сохранёнными ответами API;
страницы и их канонические URL различаются.

Список страниц — `data/kb_sources.json`, очищенный снимок исходников со ссылками,
ревизиями и контрольными суммами — `data/source_snapshot.json`.
Источники, авторство и лицензия CC BY-SA 3.0 описаны в [DATA_SOURCES.md](DATA_SOURCES.md).
В индекс попадёт **только `knowledge_base/*.md`**: словарь и исходные названия останутся вне контекста LLM.

Повторная сборка без скачивания и проверка:

```bash
python prepare_knowledge_base.py --offline
python prepare_knowledge_base.py --check
python -m unittest discover -s tests -v
```

Новые имена и их связи отсутствуют в исходной вики. Само переименование не доказывает,
что модель перестала узнавать сюжет. Поэтому на следующих этапах проверю вопросы именно
о новых названиях и сравню локальные ответы с контекстом и без него. Например:
«Какое устройство создаёт Tasklings?» и «Какая жидкость используется в Rift Spindle?».

## Задание 3. Создание векторного индекса

Использовал выбранную ранее [intfloat/multilingual-e5-base](https://huggingface.co/intfloat/multilingual-e5-base):
768 измерений, локальный запуск через Sentence-Transformers. Версия модели закреплена:
`d128750597153bb5987e10b1c3493a34e5a4502a`. Для документов добавляется `passage: `,
для запросов — `query: `; векторы нормализуются. Облачные API и LLM не используются.

Скрипт `build_index.py` читает только документы из `knowledge_base/`. Словарь замен,
исходный снимок и отчёты в индекс не попадают. Разбиение сделано через
`RecursiveCharacterTextSplitter`: сначала по абзацам и предложениям с целью 200 слов
и перекрытием 30 слов, затем проверяется длина токенизатором E5. Короткие остатки
объединяются или дополняются соседним контекстом из того же документа.

Получилось **120 чанков из 36 документов**. Размер — 100–261 слово, кроме одного
документа `taskling_cradle.md` на 97 слов: он сохранён целиком без искусственного дополнения.
Текст ограничен 450 токенами; дополнительно проверяется полный вход с префиксом и
заголовком, чтобы он не превышал 512 токенов. Фактический максимум — 409, обрезания нет.

Для каждого чанка сохраняются текст, ID, порядковый номер, путь к файлу, заголовок,
разделы, SHA-256 источника, начальная и конечная строки и символьные позиции.
Позиции считаются в символах Python: начало включительно, конец исключительно;
строки нумеруются с 1. Текст чанка в точности совпадает со срезом исходного документа.

Векторы загружены в FAISS `IndexFlatIP`. Скалярное произведение нормализованных векторов
соответствует cosine similarity. Файлы результата:

- `vector_index/faiss.index` — 120 векторов размерности 768;
- `vector_index/chunks.jsonl` — тексты и метаданные в порядке строк индекса;
- `vector_index/manifest.json` — версия модели, параметры, контрольные суммы и замеры.

Эмбеддинги считались **41,652 с**, сборка с загрузкой модели из локального кэша —
**47,464 с**. Режим: CPU, 4 потока, batch size 8, float32. Первое скачивание модели
не входит в этот замер. Время на другом оборудовании будет отличаться.

Поиск запускается через `search_index.py` и использует ту же версию E5 с `query: `.
При загрузке проверяются контрольные суммы индекса и метаданных, размерность,
количество векторов, актуальность исходников и точность позиций для цитирования.

```bash
python -m pip install -r requirements-index.txt
python build_index.py
python search_index.py "Какое устройство создаёт Tasklings для выполнения одной задачи?" --top-k 3
python evaluate_retrieval.py
```

После первой загрузки модели пересборка работает с `--offline`, поиск — без сети.
Проверил шесть вопросов из `data/retrieval_questions.json`: ожидаемый источник найден
на первой позиции в 6 из 6 случаев, необходимые подтверждения есть в top-5.
Это Source Hit@1/5, а не Recall@5: полная разметка всех релевантных чанков не выполнялась.

| Пример запроса | Первый источник | Cosine similarity |
| --- | --- | --- |
| Какое устройство создаёт Tasklings для выполнения одной задачи? | `taskling_cradle.md`, строки 1–11 | 0,8150 |
| Какую долю энергии Nezuko Delomi забирает из Lesser Realm? | `nested_realm_cell.md`, строки 11–13 | 0,8254 |
| Какой киборг был создан из Avor Kel? | `avor_kel.md`, строки 1–9 | 0,8111 |

Полные найденные фрагменты и результаты остальных запросов сохранены в
[reports/retrieval_examples.md](reports/retrieval_examples.md) и JSON рядом.
Скрипт показывает результаты поиска; это ещё не ответы бота. На этом этапе пройдены
30 тестов, включая позиции и покрытие исходного текста, ограничения размера,
сохранение/загрузку FAISS и обнаружение изменённых, добавленных или удалённых
источников и повреждённых метаданных.

## Задание 4. RAG-бот и промптинг

Сделал консольный бот `rag_bot.py`. Он использует индекс из Задания 3 и локальную
Qwen3.5-9B Q5_K_M через llama.cpp. LangChain-цепочку не добавлял: шаги пайплайна
явно видны в коде.

1. Вопрос кодируется прежней `multilingual-e5-base` с префиксом `query: `.
2. FAISS возвращает три ближайших чанка с текстом и метаданными.
3. Из инструкций, двух примеров, найденного контекста и вопроса собирается промпт.
4. Qwen формирует краткую проверку по источникам и итоговый ответ.
5. Программа проверяет цитаты и подставляет ссылки на файлы, строки и ID чанков.

Few-shot состоит из двух примеров на реальном чанке `Taskling Cradle`: ответ о том,
для чего нужно устройство, и «Я не знаю» на вопрос о массе, которой в документе нет.
Пример извлекается из сохранённого индекса; если текст изменился, загрузка примеров
завершается ошибкой. Контекст примеров не разрешён как источник для текущего вопроса.

Для CoT в системном промпте задан порядок: проверить наличие данных, привести
1–3 коротких шага с дословными цитатами, затем сформулировать ответ. Пользователь
видит объяснение по подтверждённым фактам. Внутренний монолог модели не запрашивается;
thinking выключен и в шаблоне Qwen, и в настройках сервера.

Ответ генерируется в JSON. Программа проверяет, что указанный источник присутствует
в текущем контексте, а цитата есть в его тексте. Ошибки формата, отсутствующие цитаты,
обрыв генерации и недоступность сервера выводятся как ошибки. Отказ «Я не знаю»
используется при недостатке данных. Проверки цитат не заменяют оценку смысла ответа.

Контекст — 4096 токенов вместе с резервом 512 токенов ответа. Размер считается
токенизатором Qwen с учётом chat template. При переполнении убираются последние
результаты поиска; скрытое обрезание отключено. Числовой порог cosine similarity
для отказа не задавал: близкий по теме документ может не содержать нужного факта.

Интерфейс — REPL с независимыми вопросами, без истории. Можно передать вопрос
аргументом или получить подробный результат через `--json`. Запуск:

```bash
python local_model.py download
python local_model.py serve --server /path/to/llama-server
# В другом терминале:
python rag_bot.py
python evaluate_rag.py
```

Ревизия и SHA-256 GGUF закреплены в `data/llm_config.json`. Проверенная сборка
llama.cpp — b12058. Сервер слушает `127.0.0.1:18080`; обращения в облако не используются.
Для CPU есть `--gpu-layers 0`. Установка llama.cpp и команды описаны в README.

Проверка выполнена на CPU: Ryzen 7 7700, виртуальная машина с 8 vCPU и 16 ГБ RAM,
4 потока для llama.cpp. В этой среде GPU недоступна; работу на 4070 Ti пока не измерял.

Семь вопросов из `data/rag_questions.json` отличаются от few-shot-примеров.
Получены пять ответов с подтверждёнными цитатами: о топливе Rift Weaving, доле энергии,
правительстве Vhalan Compact, киборге Avor Ember и входе и защите в Velvet Expanse.
На вопросы о точном объёме бака Rift Spindle и дате рождения Avor Kel модель ответила
«Я не знаю». Все семь контрольных случаев прошли проверку.

Диалоги без ручного редактирования — в [reports/rag_dialogues.md](reports/rag_dialogues.md).
В JSON рядом сохранены исходный ответ модели, найденные чанки, контрольные суммы,
параметры и время каждого запроса. Проверка цитат и количества токенов выполнена
по фактическим ответам сервера. Автоматические проверки статуса и контрольных слов
дополнены просмотром смысла ответов по источникам; это небольшой учебный набор.
На этом этапе проходят 44 теста. REPL проверен запуском и выходом через `/exit`.
